# CMS-V43BK 技術問い合わせ文案（未送信）

件名: CMS-V43BK 暗所でのフレームレート低下と低照度モード／速度優先制御について

サンワサプライ ご担当者様

CMS-V43BKをRaspberry Pi 5のLinux UVCドライバーから利用しています。追加照明を常時利用できない環境で、暗所でもフレームレートを維持できる設定の有無を確認したくご連絡します。

環境:

- Raspberry Pi 5、Raspberry Pi OS/Debian、aarch64
- カーネル6.12.109+rpt-rpi-2712（2026-10-31再確認）
- 製品文字列HD webcam-CMS-V43BK、メーカー文字列AONI
- USB VID:PID 1bcf:2281、bcdDevice 0.14、UVC 1.00
- 320×240、30 FPS指定

症状:

明るく照らすと約29.9 FPS取得できますが、暗くすると約16.7 FPSになります。同じカメラ・同じ取得処理を動かしたまま明暗を変えると再現します。AI処理や画面表示を外したカメラ単体の取得でも再現しました。照度は測定していません。

YUYV/MJPEG、解像度、手動露出、ゲイン、電源周波数補正、逆光補正等を比較しましたが、暗所で30 FPSを維持する設定は見つかっていません。手動露出は設定値の読出しができますが、安定した取得速度の改善に結びつきません。UVC統計の計測時点では転送エラー・不正パケットは0でした。

さらに同じカメラをMacへ接続し、AVFoundation/FFmpeg経由でも320×240・30 FPS指定で比較しました。ユーザーが明暗を確認した条件で、明るい状態約25.00 FPS、暗所約16.69 FPSでした。Apple標準APIの露出固定も受け付けられましたが、暗所の速度低下は解消しませんでした。復元後のFFmpegによる再計測でも暗所約16.71 FPSでした。このためLinux側やAI処理だけに依存する現象とは考えにくい状況です。

標準のAE_PRIORITY制御はUSBディスクリプターに広告されておらず、USBでのGET_INFO/GET_CURにも応答しません。一方で以下の拡張ユニットは存在します。

- unit 3: 7d5a1d99-5b32-428b-8cad-671b8a65f37a
- unit 6: 28f03370-6311-4a2e-ba2c-6890eb334016

確認したい点:

1. この機種の暗所でのフレームレート低下は仕様でしょうか。短い露出時間を手動指定した場合も維持される理由は分かりますか。
2. 低照度モードや自動的なフレームレート低下を無効化する設定、または速度優先設定はありますか。
3. Linuxから利用できるUVC拡張制御があれば、unit、selector、データ形式、設定値、適用タイミング、復元方法をご教示いただけますか。
4. 既存OSを維持したまま利用できる回避策や、この症状に関連する正式なファームウェア更新はありますか。
5. 暗所で30 FPSを維持できない仕様の場合、最低照度30 Lux以上という仕様との関係、およびフレームレートが低下する条件をご教示いただけますか。

必要であればUSBディスクリプターや設定一覧、再現手順を追加で提出できます。よろしくお願いいたします。

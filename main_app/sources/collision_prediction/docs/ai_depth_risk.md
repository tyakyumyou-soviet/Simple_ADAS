# AI奥行き融合の危険判定

AI奥行きON時は、従来の画像・追跡ベースの警告に加えて、相対奥行き、進路との重なり、対象の拡大・画像フローから追加の危険判定を行う。OFF時は従来方式を使用する。既存より強い警告はAI側の弱い結果で消さない。

## 入力と出力

- SCDepthV3のlogitsをModel Zooの逆深度変換に従って処理する。メートル単位に換算しない。
- 各対象について相対的な近さ、進路との重なり、短時間の横移動からの進路侵入候補、接近の証拠、情報品質を計算する。
- 正面・左前・右前は、対象の位置と同じ高さでの走行台形の幅から判定する。左右区分は画面内の方向で、校正済み方位角ではない。
- `ai_depth_collision`（YOLO対象）と`ai_depth_obstacle`（未分類領域）が実際の警告を生成する。同じ対象の衝突系警告は強い方にまとめる。
- 診断情報は`ai_depth_regions`、判定方式は`risk_mode`、CPU分析時間は`ai_depth_analysis_ms`に含む。品質値は経験則による指標で、正答確率ではない。

## 判定

1. YOLO対象は枠の中央部分の深度を取り出し、確認済み追跡IDに関連付ける。
2. 未分類候補は縮小深度画像の近い領域と、路面に予想される縦方向の深度傾斜との差・平坦な立面の候補から抽出する。YOLO枠を除外して重複を減らす。路面マスクによる一律除外はしない。
   ボンネット等の誤検出を減らすため、未分類領域は画面下20%を表示・判定範囲から外し、候補の外接枠の高さの35%以上がそこに入る場合は上側の断片も捨てる。車・人などのYOLO検出には適用しない。未分類の障害物が画面下部にしか映らない場合は検出できなくなる。
3. 未分類領域を重なりで対応付け、負のIDで管理する。新しい深度画像で消えた候補は残さない。
4. 深度の更新時刻に基づく履歴から動きを評価する。YOLO対象は枠の拡大を利用し、未分類候補の接近には画像特徴点の拡大も必要とする。深度領域の大きさの変化だけでは接近としない。
5. 画像フローから回転・平行移動を補正し、拡大成分を評価する。大きい回転・急変時は接近判定を保留する。特徴点が不足する壁では高い危険度を推定できない場合がある。
6. 背景の画像変形が小さく対応点が安定している場合のみ、全体の深度尺度のずれを補正して、既知対象の深度変化を補助的に使う。
7. 継続確認、相対的な近さ、進路重複、接近の証拠が揃うと注意を生成する。強い注意には更なる拡大と3回以上の観測を要求する。未分類候補の警告文は「正面障害物」「左前障害物」「右前障害物」とし、危険度は警告レベルで区別する。

現在の重みや閾値は初期値であり、実映像で校正されたものではない。近さは画像内で正規化した値であり、一定の値を「何m以内」と解釈しない。画像内の物体構成が変化すると相対値も変わるため、近さだけで接近警告を出さない。

立面抽出にはsigmoidで飽和する前のlogitsの形状を使い、時間的な深度変化には逆深度の対数を使う。表示用のカラーマップから危険度を計算しない。

## 結果の寿命と低品質入力

- 暗すぎる・単色・非有限・深度差が不足する入力は「判定困難」とする。
- 結果の有効期間は設定の`depth_max_age_s`（既定1.5秒）と選択した間隔から求める期間の短い方に制限する。期限切れ・時刻逆行・取得失敗時は深度履歴とAI由来警告を無効化する。
- 更新間隔中、YOLO対象は重なる追跡枠でだけ結果を関連付ける。未分類領域は最大12.5Hzの疎な特徴点追跡で位置を補う。追跡に失敗した領域では次の深度更新まで警告を保留する。どちらも深度の撮影時刻を更新せず、描画には深度の経過時間を表示する。
- AI奥行きが使えない間も従来の2D警告は動作するが、AI奥行きON時は実距離に依存する従来の車間距離警告は使用しない。

## 表示・速度

`hailo_scene.vehicle_exclusion_polygon` に `[x, y]` の0〜1正規化座標を3点以上指定すると、未分類障害物からその多角形を除外する。例: `vehicle_exclusion_polygon: [[0.3, 0.85], [0.7, 0.85], [0.8, 1.0], [0.2, 1.0]]`。実際の設置映像に合わせて設定する必要があり、未指定時は従来の下20%除外を維持する。YOLO対象には適用しない。追跡更新中は、候補枠の35%以上が多角形に重なれば保留するため、近接障害物が除外領域と重なる場合の見逃しに注意する。

候補の奥行き集計には外接枠全体ではなく連結領域の画素を用いる。一時消失した未分類候補は有効期限内だけ再対応のために履歴を残し、再検出までは警告しない。候補が入れ替わる可能性があり、正しい追跡を保証しない。

サイドバーで0.2、0.4、0.6、0.8、1.0秒を選べる。動画は映像時刻、カメラは撮影時刻を使用する。選択は再生中に反映され、プロファイル保存で保持できる。

未分類障害物として警告した領域は、奥行き画像の表示設定にかかわらず方向名付きの四角い枠を表示する。枠は候補の外接矩形であり、物体の正確な輪郭ではない。「AI奥行き画像を左上に表示」をONにするとヒートマップと既知対象の診断情報も描画する。UIにはAI融合の状態を表示する。

候補解析は幅160px、特徴点上限160、未分類領域上限12で、深度更新時だけ実行する。更新間隔中の追跡は特徴点上限120とし、未分類領域があるときだけ行う。追加のAIモデルは使用しない。Hailo推論は現在の共有デバイス上で順番に実行し、CPUの候補処理も同じ解析ワーカーを使用する。GPU/CPUの並列化や実行順の自動最適化は未実装。

## 検証と残る課題

回帰テストは、既知対象の接近、側壁の平行通過、深度マスクの変化だけによる誤警告、未分類壁の接近、路面傾斜、暗所、深度不正、全体の尺度ずれ、期限切れ、追跡ずれ、重複警告、方向と剛体移動を対象とする。

2026-11-01のPi上の短区間確認では、保存済み30FPS動画の90フレームを0.2秒間隔の深度更新で処理した。画面描画を除いた速度はOFF 59.7FPS、ON 44.8FPS、ONの全処理時間の中央値22.6ms・95パーセンタイル58.9ms、新しいCPU奥行き判定部分の中央値0.32ms・95パーセンタイル4.28msだった。YOLOとSCDepthV3のHailo実行を確認した。これは各条件1回の短い動作確認で、カメラ/GUIの速度や検出精度を示すものではない。候補表示の画像も確認した。

同日の追加確認では、手元のMy Movie 3から20秒、70秒、120秒、180秒付近を各6秒、計720フレーム抽出し、深度間隔0.6秒でOFF/ONを比較した。画面描画なしのON処理速度は各区間約52.8、49.9、42.6、43.6 FPS、OFFは約61.1、56.1、47.9、49.3 FPSだった。720フレーム中95フレームで「奥行きの差が不十分・判定困難」が表示され、これは推論回数ではなく状態が継続した表示フレーム数である。180.63秒付近では路面・ボンネット付近が障害物候補として囲まれる例を目視で確認した。20秒付近では動画に再生UIが重なる場面もあり、70秒付近には夜間場面がある。正解ラベルや壁接近場面を含む十分な評価データはなく、この確認から全体の誤検出率・見逃し率や壁への性能を求めることはできない。

下部除外の検証では、同じ動画の180秒付近の6秒間について未分類障害物警告が出たフレームが48から0になり、180.63秒付近の路面・ボンネット候補も出なくなった。20秒付近の6秒間では警告フレームが24から6に減り、22.5秒の左前の壁候補は下端を切った形で残った。未分類障害物の警告全体が減っているため、他の有効な候補も消える可能性があり、これらの数は正解ラベルに基づく精度ではない。YOLO対象の単体テストと合成した高い壁の候補維持も確認した。

次の実映像評価では、壁への接近・停止・平行通過、車・歩行者の侵入、旋回、振動、夜間を用い、ON/OFF別に見逃し、誤警告、警告時刻、映像FPS、YOLO更新速度、推論・CPU分析時間を比較する。既存の走行動画だけでは壁・暗所の検出精度を結論づけない。

無地の壁、ガラス、反射、影、急な照明変化、画角外の障害物、実車の旋回経路、細い障害物は限界がある。カメラ校正・実距離化・壁種別の識別・信頼性の統計的校正は未実装。自動運転や制動制御には使用しない。

# 車線・危険判定・速度の修正計画

作成日: 2026-11-01。計画段階であり、以下の変更は未実装。

## 実装状況（2026-11-01追記）

- サイドバーの「曲線車線（試験中）」を追加。既定OFF、ON時はIPMの2次曲線を24点ずつに変換し、表示と進路領域に使用する。曲線モードだけ直線フォールバックを止め、切替時に履歴を解除する。
- 車の画面内速度から前後を決める処理を廃止。ランプの画像特徴を使い、後部は継続確認してから車間警告の対象とする。向き不明・前面の対象には車間という文言を使わず、条件に応じた接近警告を維持する。ランプ判定は経験則であり、後部識別の正確さは保証しない。
- 歩道とされた対象でも、信頼できる横からの進路侵入候補なら飛び出し判定へ渡す。側方侵入に追跡の確認・動きの有効性・対応品質の条件を追加。
- 日本語文字の全画面PIL変換を廃止し、上限付きの文字画像キャッシュと局所合成へ変更。非同期カメラの描画時間と撮影から出力までの時間を性能ログへ追加。
- 実カメラ別の車体範囲の校正、壁の無模様領域の追跡改善、局所路面判定、新モデルの導入、前後を高精度に識別するモデルは未実施。実例のない場面を正しく判定できるとは主張しない。

## 前提と順序

速度を最優先とし、ver28以降の現在の作業状態を変更前の比較基準として保存する。画面表示、入力、YOLO、車線、深度、警告の更新速度と撮影から表示・警告までの時間を区別する。新しいAI推論を常時増やす場合は事前に実機で負荷を測る。MyMovieは場面とカメラが切り替わる編集動画であり、壁接近や飛び出しの正解映像を網羅していない。

1. Piの現在のソースとMacを比較し、既存変更を保護した上で、実行環境・モデル・プロファイルを記録する。アプリ全体の動画再生とログを確認し、過去の動画停止を再検証する。
2. 描画・検出数・推論・警告ごとの負荷を同一映像・同一設定で計測する。0.6秒の奥行き更新、対象数別の表示FPS、フレーム時間中央値/95%点、入力から表示までの遅れを比較する。最初に測定の揺れを確認する。
3. 車線の曲線モードを追加し、既存のオフ時挙動を回帰確認する。
4. 車両の向きと車間/衝突の警告を整理し、対向・前車・向き不明を別々に検証する。
5. 歩行者の横からの侵入を検証し、歩道判定や追跡条件の見直しを行う。
6. 残っている奥行きの路面比較、車体マスク、追跡・判定理由の調整を比較し、効果と負荷を測って採否を決める。
7. 修正ごとにテストと実映像比較を行い、完了後Piに反映してアプリを再起動する。変更と結果、未評価の範囲を報告する。pushは別途明示依頼がある場合のみ行う。

## 1. 曲線車線モード

- サイドバーに「曲線車線（試験中）」チェックを追加する。既定OFF。OFFでは既存のプロファイル・車線方式をそのまま使い、ONで曲線対応の別経路へ切り替える。入力中の切替、停止・再開、プロファイル変更と保存時の挙動を明示し、古い直線・曲線の履歴は混ぜない。
- 既存IPM処理には2次曲線のフィットがある一方、画像への変換は端点を使った表現で、描画・危険判定の一部は四角形や直線を前提にする。これを調査し、画像上の複数点から左右の曲線と間の領域を生成する。ONのときだけ試験経路で使う。
- 左右線の交差、幅の急変、支持点不足、遮蔽、急激な曲率変化を確認する。検出できない場合は検出不能として扱い、誤った曲線を延々と保持しない。短時間の補間の上限と、観測と推定を区別する表示を設ける。
- 描画だけ曲げず、進路領域、歩行者侵入、障害物方向、車線逸脱判定も曲線に沿うよう整合させる。現行LDWは4点ポリゴンの特定インデックスを前提にしているため、そのまま多点ポリゴンを渡さない。車両から近い位置の左右境界を明示的に求める。
- 直線・左右カーブ・遮蔽・車線なし・場面切替を検証する。曲線で結果が不安定ならその状態を表示する。追加負荷は車線更新時だけに抑える。

## 2. 車間注意と対向車

### 現状

`RiskAnalyzer`は車両の向きと動きを推定するが、現在の前後推定はライトの色などに加え画像上の縦方向速度にも依存する。対象が接近することと、車両の前面が見えていることは同じではない。また、危険スコアのレベル2は向きに関係なく「車間注意」と表示し得る。AI奥行きON時、現行は物体のメートル距離を無効にするため、相対深度を8mや15mのような実距離として使えない。

### 方針

- フロントカメラについて、車体の見えている面を `後部 / 前部 / 側面 / 不明` とし、相対接近・離反、進路への侵入は別の情報として扱う。車体面の推定には信頼度と複数観測の安定性を持たせる。ライト色や画面内の速度だけで確定しない。
- 同一進路上で後部が十分な根拠をもって見え、近さ・接近の根拠も満たす場合に「車間注意」。対象の前部や側面が見える対向・横断車は進路侵入や接近に応じた「衝突注意／接近注意」とする。
- 向きが不明な対象を単に無視しない。進路と接近の根拠に応じて対象不明の「前方接近注意」などを使い、車間と断定しない。危険度判定とメッセージの決定を分ける。
- AI奥行きON時は相対的な近さと画像の拡大を条件にできるが、距離やTTCを測定値のように表示しない。通常方式の距離計算も校正・根拠を確認する。
- 前部・後部の識別に十分な既存情報があるかをまず測る。不足するならモデルの追加、Hailo-8対応、入力画素、実速度とライセンスを調査して比較し、未検証の分類を高信頼として使わない。将来のリアカメラ用にカメラ方向を明示する設計を準備し、今回は前方カメラで検証する。
- 前車、対向車、駐車車両、後退、横断、遮蔽、夜間、向き不明を別に評価する。誤警告だけでなく見逃しも確認する。

## 3. 人・自転車の飛び出し

### 現状

横からの侵入と飛び出しの判定は既存だが、前段で歩道と判定されると後続の危険判定まで到達しない経路がある。側方侵入はレーンポリゴン、位置、画像速度の閾値と軌跡予測に依存する。追跡履歴や自車動きの推定、実際の更新周期・速度単位も検証が必要。検出できたが警告できなかった原因を実例なしに断定しない。

### 方針

- 歩道上に見える対象でも、進路方向への移動、現在の枠、予測位置が危険領域に迫っている場合は飛び出し候補として評価する。歩道を歩くだけの人を一律に警告しない。
- 左右からの出現、進路へ向かう横移動、進路との重なり、画像上の近さ、追跡の品質、自車の停止・移動状態をそれぞれ記録する。画素/フレームと画素/秒、フレームの欠落やFPS変化を区別する。
- 画面端から突然出た対象は、履歴が少ない状態でも候補として扱うが、不確かな最初の検出だけで最強の警告にしない。予測の時間幅と警告条件を映像で検証する。
- 前景の歩行者の認識と衝突系の警告が深度融合後に消されないか、重複警告も含めて確認する。
- 左右の飛び出し、止まっている歩行者、歩道を平行に歩く人、画面端の誤検出、自車旋回を含む映像で、対象単位の見逃し・誤警告・警告開始時刻を比較する。MyMovieに必要場面がない場合は、実映像性能を未評価と明記する。

## 4. 描画と速度

現コードは物体の枠・複数ラベル・警告を描き、日本語文字の描画ごとに画像をPILへ変換している。描画時間が対象数で増える可能性はあるが、後処理や追跡、深度処理も対象数の影響を受けるため、実測前に原因を断定しない。動画側のpipelineにはrender時間の計測があるが、非同期カメラ側の描画も別に測る。

- 物体数ごとに、推論、追跡、危険判定、枠、日本語文字、画面への転送を計測する。奥行きプレビューON/OFFも同条件で比較する。
- 描画が支配的なら、文字描画を一括化または必要範囲だけ更新し、フォント・テキストをキャッシュする。奥行きヒートマップは深度更新時に作って再利用する。結果の期限切れと表示サイズ変更時には再生成・消去する。
- 表示は必ずしも全フレームで再描画する必要がないが、警告状態と新しい映像の更新遅れが増えないようにする。表示の品質を落とす場合は明示的に設定可能とする。
- 処理FPSだけでなく、入力FPS、表示FPS、撮影から表示・警告までの時間、奥行き結果の年齢を測る。仮目標は同条件で表示FPS低下3%以内、表示遅延95%点の増加5ms以内。実測のばらつきと入力FPS上限を考慮して判定する。

## 5. 継続中の奥行き・動画の課題

- 現在の画面下20%の除外は、未分類の低い障害物を見逃し得る。カメラ別ポリゴンの設定機能はあるが、実カメラへの設定と検証は未完了。設定後も対象と除外範囲の重なりによる見逃しを調べる。
- 相対深度候補に路面が混ざらないか、局所的な路面傾向と連結領域を比較する。車や壁が路面推定を汚染しない条件と、路面が見えない時の判定保留を設ける。
- 特徴点の少ない壁での追跡失敗は、近い対象がない証拠にしない。限定範囲で輪郭やブロック照合を試し、追加負荷と誤対応を測る。
- 候補の検出理由・除外理由を評価時に記録する。時系列の平滑化は急接近の警告を遅らせないかを確認する。
- 映像全編の推論・描画経路は一度通過済みだが最終版の全GUI再生ではない。アプリ本体での動画再生と表示例外のログも確認する。

## 採用条件と未評価の扱い

各変更は既存と同条件で比較し、速度、イベント単位の誤警告・見逃し・警告時刻を併記する。正解ラベルのない警告フレーム数だけで精度改善と判断しない。カーブ、対向車、飛び出し、壁接近に必要な実映像がなければ合成テストでコードの振る舞いを確認し、実映像の性能は未評価として残す。危険警告に用いるため、自動制動や運転の代替とみなさない。

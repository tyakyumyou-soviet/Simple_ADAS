# Pi 速度改善と実機計測（2026-10-30）

## 変更

- Pi 高速プロファイルは動画の初期設定を実時間優先とし、YOLOと従来車線の目標更新周期を各10 Hzに設定。AI車線とAI奥行きはOFF。
- 実時間スケジューラが周期の端数を持ち越し、低速入力でYOLOが車線を継続的に妨げないよう修正。
- プレビューのFPS表示を、起動時からの累計平均ではなく直近のUIフレーム受け取り速度に変更。
- Piデスクトップに元動画を保持し、全編の640×360 H.264変換版を作成。元映像より細部が失われる。

## 同一環境での短時間計測

Pi 5、Hailo-8、YOLO26n、320幅で解析。Qtのオフスクリーンのフレーム受け取りであり、Pi Connect転送・モニター描画・センサー露光からの遅延は含まない。値は各10～15秒の概数。

| 入力 | 条件 | 受取 FPS | YOLO回/秒 | 車線回/秒 |
|---|---|---:|---:|---:|
| カメラ 320×240 | 変更前、目標各5 Hz | 15.0 | 4.2 | 4.2 |
| カメラ 320×240 | 目標各10 Hz、旧周期計算 | 15.4 | 8.3 | 8.3 |
| カメラ 320×240 | 目標各10 Hz、周期修正後 | 15.6 | 9.9 | 10.0 |
| 元動画 3144×1764 HEVC | 全フレーム、10 Hz設定 | 16.6 | 未計測 | 未計測 |
| 元動画 3144×1764 HEVC | 実時間優先、10 Hz、周期修正前 | 8.6 | 7.1 | 3.8 |
| 軽量版 640×360 H.264 | 実時間優先、10 Hz、周期修正前 | 29.8 | 8.3 | 7.9 |
| 軽量版 640×360 H.264 | 実時間優先、10 Hz、周期修正後 | 29.8 | 10.0 | 10.0 |

全フレームは遅くなってもフレームを処理し、実時間優先はフレームを飛ばすため、FPSだけで両者の再生時刻の正確さを比較できない。特に元動画はフレームを捨てる際のデコードも重い。

カメラはV4L2直接取得でも約15～16 FPS。YUYV/MJPEGや異なる解像度でも同様。カメラを開いた後に手動露出10msへ変更した短い試行では約18 FPSだったが、画質や環境による差は未検証。露出は元の自動設定と値に戻した。HEVCのV4L2 mem2memデコーダーは有効なデバイスを見つけられなかった。

回帰確認ではスケジューラの車線飢餓・周期と既存のプレビュー・動画モードを確認した。pytestはPi環境にないため該当関数は直接実行した。実車環境での長時間動作、検出精度、車線・警告・TTC、Pi Connect経由の遅延、安全性は未検証。
